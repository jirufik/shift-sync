# ocr-bench — стенд проверки распознавания

Регрессионный тест парсера ORTEC ESS и шлюза валидации.
Метрика: **доля дней, где дата, начало и конец совпали одновременно** с эталоном.

## Запуск

```bash
pnpm install
node run.mjs        # OCR по samples/ess/ → raw-v5-salvage.json
node score.mjs      # разбор + валидация + сверка с эталоном
```

Из корня то же самое: `pnpm bench` (только сверка по сохранённой выдаче).

## Кадры

По умолчанию стенд гоняется на синтетических снимках `samples/ess/` — их рисует
`tools/samples/make-screens.mjs` из выдуманного графика `tools/samples/schedule.mjs`.
Человек, магазин и смены не существуют. Эталон — константа `GT` в `score.mjs`.

Свои снимки прогоняются так же, но держатся вне репозитория (`private/` в `.gitignore`):

```bash
node run.mjs ../../private/samples/ess ../../private/samples/ess/ocr.json
```

Сохранённая выдача и эталон в `private/samples/ess/` подхватываются тестом
`apps/api/test/private-samples.spec.ts`; без них этот тест пропускается.

## Результат на синтетических кадрах

Модель `V5_LATIN_MOBILE_MODEL` (PP-OCRv5 latin mobile), `maxSideLength: 1280`,
добор потерянных боксов включён.

```
Совпало: 9/9   Расхождений: 0
три прогона подряд дают одинаковую выдачу
```

В трёх днях OCR потерял одно из времён в левой колонке, и время восстановлено из
заголовка карточки (`*` в отчёте). На реальных снимках стенд тоже давал 9/9.

## Файлы

| Файл | Назначение |
|---|---|
| `recognize.mjs` | обёртка над ppu-paddle-ocr + добор потерянных боксов |
| `parser.mjs` | закрытый финский словарь, парсер вёрстки ORTEC, шлюз валидации |
| `score.mjs` | сверка с эталоном, отчёт |
| `run.mjs` | прогон OCR по каталогу кадров |
| `raw-v5-salvage.json` | сохранённая выдача OCR по `samples/ess/` |
