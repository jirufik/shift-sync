# Shift Sync — архитектура сервиса

Чтение рабочего графика из **ORTEC Employee Self Service** — снимками экрана или выгрузкой в PDF — и синхронизация смен в Google Календарь «Смены».

**Дата:** 7 сентября 2026 (импорт из PDF добавлен; первая версия — 27 августа 2026)
**Статус:** реализовано. Код в этом же репозитории, запуск — `README.md`, журнал решений — `DECISIONS.md`.

---

## 1. Что делает сервис

```
  телефон                  сервис                                  Google
 ┌────────┐   загрузка   ┌──────────────────────────────────┐   ┌──────────┐
 │ скрины │ ───────────► │ 1a. OCR: PP-OCRv5 + словарь      │   │ Календарь│
 │ ORTEC  │         ┌──► │ 1b. PDF: текстовый слой файла    │   │  «Смены»  │
 ├────────┤         │    │ 2.  парсер вёрстки / таблицы     │   └──────────┘
 │  PDF   │ ────────┘    │ 3.  валидация (детектор ошибок)  │        ▲
 │ ORTEC  │              │ 4.  склейка перекрытий           │        │
 └────────┘              │ 5.  диффинг с текущим состоянием │        │
                         └───────────────┬──────────────────┘        │
                                         ▼                           │
                              ┌─────────────────────┐                │
                              │ экран ревью:        │   применить    │
                              │ дата │ было │ станет│ ──────────────►│
                              │ можно поправить     │                │
                              └─────────────────────┘
```

Один пользователь, вход по паролю из ENV. Работает бесплатно: распознавание локальное, Google Calendar API бесплатен.

## 2. Принятые решения

| Решение | Выбор | Почему |
|---|---|---|
| Применение в календарь | **Ревью перед записью** | Ошибка распознавания молча перезапишет смену. Ревью — единственная защита |
| Дни «нет смены» | **Удалять смену на эту дату** | `Sinulla ei ole työvuoroa` — это утверждение, а не пустота. Иначе отменённая смена висит вечно |
| Распознавание снимков | **Локально, единственный путь** | Раздел 6. PP-OCRv5 внутри процесса Node. Без переключателей и без облака (D-004) |
| Выгрузка PDF | **Читается текстовым слоем, без OCR** | 6.7. В файле настоящий текст с координатами; распознавать его — вносить ошибку туда, где её нет (D-028) |
| Отпуск и служебные метки | **В календарь не идут** | 6.7. `Vuosiloma` неотличим от смены по времени; опознаётся по названию активности (D-032) |
| Дни за границей публикации | **Не трогаются вовсе** | 6.7. За датой `Julkaistu` день пуст всегда — верить этой пустоте нельзя (D-032) |
| Аутентификация Google | **Сервисный аккаунт** | Без OAuth, без экрана согласия, без протухающих токенов. Раздел 8 |
| Масштаб | **Компактное монорепо** | Привычные конвенции NestJS-монорепо без Kafka/Redis/OTel: один `api` + один `web` |
| Источник правды | **PostgreSQL**, календарь — проекция | Диффинг и повтор при сбое возможны только при своём состоянии |

## 3. Что показал разбор исходных данных

Разбирались три реальных скрина вкладки «TYÖVUOROLISTA». Сами снимки в репозиторий не входят; все примеры ниже — из выдуманного графика (`tools/samples/schedule.mjs`), синтетические кадры с ним лежат в `samples/ess/`. Из снимков вытащены требования, которых не было в постановке.

### 3.1. Структура экрана

```
┌─────────────────────────────────────────┐
│  maaliskuuta 2027        ← шапка: месяц + ГОД
├─────────────────────────────────────────┤
│  ▌Haluatko lisää työvuoroja?   ← липкий баннер, перекрывает контент
├─────────────────────────────────────────┤
│  ○ maanantai, maaliskuuta 15 ← заголовок дня: день недели + месяц + число
│    ┌───────────────────────────────┐
│    │ 07:00 ▌ 410 7-14              │  ← время дублируется: колонка + заголовок
│    │ 14:00 ▌ Demo Market           │
│    │       ▌ Vuoroaika: 7 h,       │  ← контрольная сумма длительности
│    │       ▌ Työaika: 7 h          │
│    └───────────────────────────────┘
```

### 3.2. Три вида записей, а не один

| Что на экране | Что это | Что делать |
|---|---|---|
| `07:00 / 14:00`, `410 7-14`, `Vuoroaika: 7 h` | Рабочая смена | Завести/обновить |
| `Sinulla ei ole työvuoroa tänä päivänä` + иконка дома | Явное «смены нет» | Удалить смену на эту дату |
| `TES V`, `01:00 / 01:01`, иконка луны | Служебная метка на 1 минуту, **не смена** | Отбросить |

Запись `TES V` — главная ловушка. Без фильтра она превратится в фантомное событие в календаре.

### 3.3. Перекрытие скриншотов

Скрины сняты прокруткой одного списка, поэтому:
- одна и та же дата встречается в двух файлах → нужна дедупликация;
- карточки на верхней и нижней кромке обрезаны (`Vuoroaika: 7 h` без заголовка дня) → обрезанные записи отбрасываются, их подберёт соседний скрин;
- липкий баннер перекрывает контент → нельзя считать, что верх изображения = начало списка.

### 3.4. Три независимых источника одного факта

Это ключ ко всему качеству распознавания. Одна и та же смена закодирована трижды:

1. **Левая колонка** — `07:00` / `14:00`
2. **Заголовок карточки** — `410 7-14`
3. **Строка длительности** — `Vuoroaika: 7 h`

Плюс **день недели рядом с числом**: он обязан совпасть с настоящим календарём для этой даты. На синтетических кадрах:

```
2027-03-07 → sunnuntai   ✓      2027-03-11 → torstai    ✓
2027-03-08 → maanantai   ✓      2027-03-12 → perjantai  ✓
2027-03-09 → tiistai     ✓      2027-03-13 → lauantai   ✓
2027-03-10 → keskiviikko ✓      2027-03-14 → sunnuntai  ✓
                                2027-03-15 → maanantai  ✓
```

**Следствие:** нам не нужно доверять распознаванию. Нужен детерминированный шлюз, который проверяет согласованность четырёх независимых сигналов и отбраковывает всё, что не сошлось. Это бесплатно, работает офлайн и ловит галлюцинации любой модели.

### 3.5. Закрытый словарь

Весь «сложный» текст, который надо прочитать, — это числа и **19 финских слов**:

```
дни:    maanantai tiistai keskiviikko torstai perjantai lauantai sunnuntai
месяцы: tammikuuta helmikuuta maaliskuuta huhtikuuta toukokuuta kesäkuuta
        heinäkuuta elokuuta syyskuuta lokakuuta marraskuuta joulukuuta
```

Нечёткое сопоставление (Левенштейн ≤ 2) с этим списком вытягивает даже посредственный OCR: `syyskuute`, `syvskuuta`, `syyskuufa` — всё однозначно схлопывается в `syyskuuta`. Это второй большой рычаг качества, и он тоже бесплатный.

### 3.6. Что показал разбор PDF-выгрузки

Разбирались две реальные выгрузки: за месяц и за несколько дней следующего. В репозиторий они не входят; синтетические аналоги с той же геометрией — `samples/pdf/`. Отчёт печатает Microsoft Reporting Services, и в нём лежит настоящий текстовый слой с точными координатами строк. Из него вытащены требования, которых на экране приложения не видно.

**Таблица шире, чем карточка на экране.** Семь колонок: дата, место, время смены, код смены, примечание, время активности, активность. Одна строка на календарный день — включая дни без смены, у которых колонки просто пусты. Это то же утверждение, что фраза `Sinulla ei ole työvuoroa` на экране.

**Код смены не гарантирует времени.** День бывает помечен шаблоном `410 7-14`, а работа идёт 06:45–13:45 (в образце — 4.4.2027). На экране заголовок карточки был честным третьим источником времени; здесь он — имя шаблона, и сверять по нему нельзя. Его место занимает расшифровка смены по активностям: начало первой и конец последней обязаны сойтись с краями смены.

**Отпуск занимает строку смены.** `Vuosiloma` записан как `09.00 - 15.00` — так отпускной день засчитывается в баланс часов. По времени он неотличим от рабочего дня.

**Пустой день не всегда выходной.** В шапке указано, до какой даты график опубликован, и там же предупреждение: «Shifts in schedules with status plan are not shown». За этой границей день пуст всегда.

**Переносы внутри ячейки рвут и слова.** Узкая ячейка ломается и по пробелу (`410` / `Tupakka/k` / `assa`), и посреди слова (`1-` / `Kassalinjasto`). Режим чтения `preserve-whitespace` сохраняет пробел на переносе, поэтому ячейка собирается обратно простой склейкой.

## 5. Модель данных

```sql
-- одна загрузка = один батч
CREATE TABLE import_batches (
  id             uuid PRIMARY KEY,
  status         text NOT NULL,          -- pending|recognizing|review|applying|applied|failed|cancelled
  source_month   date,                   -- 'maaliskuuta 2027' -> 2027-03-01
  provider       text,                   -- какой распознаватель отработал
  stats          jsonb,                  -- {recognized, valid, needsAttention, created, updated, deleted}
  error          text,
  created_at     timestamptz NOT NULL DEFAULT now(),
  applied_at     timestamptz
);

CREATE TABLE screenshots (
  id             uuid PRIMARY KEY,
  batch_id       uuid NOT NULL REFERENCES import_batches(id) ON DELETE CASCADE,
  file_path      text NOT NULL,          -- картинка кадра; у PDF — отрисованная страница
  sha256         text NOT NULL,          -- дедуп повторной загрузки того же файла
  width          int NOT NULL,
  height         int NOT NULL,
  order_index    int NOT NULL,
  source_kind    text NOT NULL DEFAULT 'image',  -- image | pdf_page
  source_path    text,                   -- исходный PDF; у снимка экрана пусто
  page_index     int NOT NULL DEFAULT 0, -- номер страницы внутри PDF
  created_at     timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX ON screenshots (sha256);

-- сырой результат распознавания, до склейки и диффа
CREATE TABLE recognized_rows (
  id             uuid PRIMARY KEY,
  batch_id       uuid NOT NULL REFERENCES import_batches(id) ON DELETE CASCADE,
  screenshot_id  uuid NOT NULL REFERENCES screenshots(id) ON DELETE CASCADE,
  kind           text NOT NULL,          -- shift|no_shift|non_work_marker|unparsed
  work_date      date,
  weekday_text   text,                   -- 'sunnuntai' как прочитано
  starts_at      time,
  ends_at        time,
  label          text,                   -- '410 7-14'
  location       text,                   -- 'Demo Market'
  duration_text  text,                   -- 'Vuoroaika: 7 h'
  is_clipped     boolean NOT NULL DEFAULT false,
  confidence     numeric(4,3),
  checks         jsonb NOT NULL,         -- результат каждой проверки шлюза
  raw            jsonb NOT NULL,         -- что вернул провайдер, для отладки
  created_at     timestamptz NOT NULL DEFAULT now()
);

-- целевое состояние: что должно быть в календаре
CREATE TABLE shifts (
  id                uuid PRIMARY KEY,
  work_date         date NOT NULL,
  starts_at         time NOT NULL,
  ends_at           time NOT NULL,       -- смены не пересекают полночь: ends_at > starts_at всегда
  label             text,
  location          text,
  tz                text NOT NULL DEFAULT 'Europe/Helsinki',
  google_event_id   text,
  sync_state        text NOT NULL DEFAULT 'pending',   -- pending|synced|failed
  sync_error        text,
  source_batch_id   uuid REFERENCES import_batches(id),
  created_at        timestamptz NOT NULL DEFAULT now(),
  updated_at        timestamptz NOT NULL DEFAULT now(),
  UNIQUE (work_date, starts_at)          -- допускаем несколько смен в один день
);
CREATE INDEX ON shifts (work_date);
CREATE INDEX ON shifts (sync_state) WHERE sync_state <> 'synced';

-- журнал: что и почему сделали с календарём
CREATE TABLE sync_log (
  id              uuid PRIMARY KEY,
  batch_id        uuid REFERENCES import_batches(id),
  work_date       date NOT NULL,
  action          text NOT NULL,         -- create|update|delete|skip_identical|skip_invalid
  before          jsonb,
  after           jsonb,
  google_event_id text,
  ok              boolean NOT NULL,
  error           text,
  created_at      timestamptz NOT NULL DEFAULT now()
);
```

Имена таблиц и колонок — `snake_case`, как в DC. Префикс БД — `fc_` (`fc_shift_sync`).

## 6. Распознавание

Приоритет: **локально, минимум ресурсов, но качество важнее всего.** Целевое железо — обычный домашний ПК: 16 потоков CPU, встроенная графика. Дискретной видеокарты и CUDA нет, поэтому ставка на CPU и лёгкие модели.

### 6.1. Единственный путь

Решением от 27.08.2026 (`DECISIONS.md`, D-004) абстракция провайдеров и второй уровень на локальной VLM из проекта **убраны**. Ресерч дал 9/9 на реальных данных, а закладывать переключатели под варианты, которые не понадобились, — это платить сложностью за гипотезу.

Конвейер целиком:

```
изображение
  → PP-OCRv5 (ppu-paddle-ocr, V5_LATIN_MOBILE_MODEL, maxSideLength 1280)
  → добор потерянных боксов          ← обязательный шаг, см. 6.3
  → парсер вёрстки ORTEC ESS
  → закрытый финский словарь (Левенштейн ≤ 2)
  → шлюз валидации из пяти проверок
  → не прошедшее шлюз → в ревью как «требует внимания»
```

Роль, которую раньше отводили второму уровню, исполняет человек в ревью: спорные строки помечены, по умолчанию не отмечены и правятся в один клик.

### 6.3. Результат проверки PP-OCRv5 · 27 августа 2026

Модель `V5_LATIN_MOBILE_MODEL` (PP-OCRv5 latin mobile), `maxSideLength: 1280` — родное разрешение, без даунскейла. Стенд — `tools/ocr-bench/`. Первый прогон шёл на трёх реальных скринах и дал 9 из 9; в репозитории их нет, поэтому таблица ниже — прогон того же стенда на синтетических кадрах `samples/ess/` (значения условные).

| дата | эталон | получено | источников | вердикт |
|---|---|---|---|---|
| 2027-03-07 | 07:00–14:00 | 07:00–14:00 | 2 | ✓ |
| 2027-03-08 | 10:00–16:30 | 10:00–16:30 | 2* | ✓ |
| 2027-03-09 | 09:00–17:00 | 09:00–17:00 | 3 | ✓ |
| 2027-03-10 | нет смены | нет смены | 1 | ✓ |
| 2027-03-11 | в ревью (TES V) | в ревью | — | ✓ |
| 2027-03-12 | 08:30–15:00 | 08:30–15:00 | 2* | ✓ |
| 2027-03-13 | 12:00–20:00 | 12:00–20:00 | 2* | ✓ |
| 2027-03-14 | нет смены | нет смены | 1 | ✓ |
| 2027-03-15 | 07:00–14:00 | 07:00–14:00 | 2 | ✓ |

**9 из 9. Расхождений нет.** `*` — время восстановлено из заголовка карточки, потому что в левой колонке OCR потерял одно из двух значений. Ровно тот случай, ради которого закладывалась тройная избыточность источников.

**Измерено:** инициализация 127 мс (модели из кэша), **~104 мс на изображение**, пик RSS процесса **~950 МБ**, три прогона подряд дают побитово одинаковый результат.

> Оценка «~150–300 МБ» из первой редакции документа была занижена: реальный пик почти втрое выше из-за onnxruntime и OpenCV WASM. Для сервиса, отрабатывающего несколько раз в месяц на домашнем ПК, это несущественно, но цифру фиксируем честно.

#### Что подтвердилось

- Финская диакритика читается без ошибок: `TYÖVUOROLISTA`, `työvuoroa tänä päivänä`, `Työaika`, `Lisää`.
- Заголовки дней прочитаны, все проверки дня недели против календаря прошли.
- `Sinulla ei ole työvuoroa tänä päivänä` — уверенность 0.99.
- `TES V` (01:00–01:01) отбракован и ушёл в ревью, **хотя сам текст прочитался с ошибкой (`TSV`, `TEV`)**. Фильтр работает по времени, а не по подписи, поэтому опечатка в метке ему безразлична.
- Обрезанная кромкой карточка отброшена, дубли между кадрами склеились по датам.

#### Что пришлось починить

**1. Добор потерянных боксов — обязательный компонент.** На одном кадре детекция нашла бокс заголовка дня, а батч-проход распознавания вернул для него пустоту. Понижение `minimumConfidence` до нуля не помогло — текста не было вовсе. Тот же кроп, поданный отдельно, читается дословно с уверенностью **0.99**.

Лечится дешёвым добором: боксы с текстовой пропорцией (`width/height ≥ 3`, `height ≥ 14`), для которых основной проход не дал текста, до-распознаются поодиночке. На трёх кадрах добор поднял 1 значимый бокс из 98 и вернул `9/9` вместо `8/9`. Стоимость — один лишний инференс на кроп.

**2. Ловушка в разборе `Vuoroaika`.** Строка `Vuoroaika: 8 h, Työaika: 7 h ja 30 min` при наивном разборе даёт 8 ч 30 мин: `30 min` из `Työaika` приплюсовывается к `Vuoroaika`. Сегмент нужно обрезать по запятой и по слову `Työaika`. Это была ошибка парсера, а не OCR — но она бы отбраковала корректную смену с неоплачиваемым перерывом как «не сошлась длительность».

#### Косметические огрехи, на результат не влияющие

заглавная `I` в начале слова читается как строчная `l`, `410 9-15.30` → `4109-15.30` (слипание, разбирается регуляркой), `LISÄÄ` → `LISÃÃ` в подписи вкладки. Ни одно из этих полей в календарь не идёт.

### 6.4. Конвейер и шлюз

```
                    ┌──────────────────────────────────────┐
  нормализация      │ sharp: приведение к 1280 по длинной  │
  изображения       │ стороне, grayscale, автоконтраст     │
                    └──────────────────┬───────────────────┘
                                       ▼
                    ┌──────────────────────────────────────┐
   РАСПОЗНАВАНИЕ    │ PP-OCRv5 in-process → текст + боксы  │
   ~104 мс на кадр  │            ↓                         │
   пик RSS ~950 МБ  │ добор потерянных боксов (6.3)        │
                    │            ↓                         │
                    │ парсер ORTEC ESS: группировка по Y,  │
                    │ закрытый словарь, извлечение полей   │
                    └──────────────────┬───────────────────┘
                                       ▼
                    ┌──────────────────────────────────────┐
     ШЛЮЗ           │ 1. день недели == реальный для даты? │
     детерминиро-   │ 2. время в колонке == время в шапке? │
     ванный,        │ 3. (end − start) == Vuoroaika?       │
     бесплатный     │ 4. длительность в 15 мин … 16 ч?     │
                    │ 5. карточка не обрезана кромкой?     │
                    └───────┬──────────────────┬───────────┘
                     всё ок │                  │ что-то не сошлось
                            ▼                  ▼
                    confidence=high      «требует внимания»
                    отмечено в ревью     снято, правится руками
```

Почему так:

- **Один проход покрывает весь объём.** Текст на скринах крупный и чёткий — самый лёгкий сценарий для OCR. 9/9 и на реальных кадрах, и на синтетических.
- **Шлюз делает систему честной.** Она не «надеется», что распозналось верно, а сверяет пять условий против четырёх независимых сигналов из раздела 3.4.
- **Неуверенность признаётся явно.** Строка, не прошедшая шлюз, не отбрасывается молча и не применяется молча: она уходит человеку с объяснением, что именно не сошлось. Эту роль в черновике архитектуры отводили второму уровню на локальной VLM — от него отказались (D-004), потому что ревью нужно всё равно.

### 6.5. Этап 0 — выполнен

Стенд собран, лежит в `tools/ocr-bench/` и прогоняется двумя командами:

```bash
npm run recognize   # OCR по fixtures/ → raw-v5-salvage.json
npm run score       # разбор + валидация + сверка с эталоном
```

Структура:

```
samples/ess/             синтетические кадры (генератор — tools/samples/)
tools/ocr-bench/
├── run.mjs              PP-OCRv5 по samples/ess/ → raw-v5-salvage.json
├── recognize.mjs        обёртка над ppu-paddle-ocr с добором боксов
├── parser.mjs           тот же разбор вёрстки, что и в сервисе
└── score.mjs            эталон + сверка, печатает «Совпало: N/N»
```

Метрика — не «процент символов», а **процент дней, где дата, начало и конец совпали одновременно**. Это единственное, что влияет на результат в календаре.

**Остальные кандидаты не проверялись и в код не заложены** (D-004). PP-OCRv5 даёт 9/9 на реальных данных; к Tesseract, Qwen3-VL, PaddleOCR-VL и Gemini возвращаемся, только если на новых кадрах появятся промахи, и это будет правка `recognition.service.ts`, а не смена переменной окружения.

Стенд гоняется при каждом изменении парсера — он же регрессионный тест. Свои кадры прогоняются тем же стендом: `node run.mjs <каталог> <файл-выдачи>`; настоящие снимки держатся в `private/` и в репозиторий не попадают.

### 6.6. Наружу не уходит ничего

Облачных провайдеров в коде нет вовсе (D-004). Скриншоты обрабатываются локально, единственный внешний запрос за всё время жизни сервиса — разовое скачивание весов PP-OCRv5 (~15 МБ) при первом распознавании.

### 6.7. Второй вход: PDF без распознавания

Выгрузка разбирается по тексту, который лежит в самом файле. OCR к ней не применяется вообще (D-028): текстовый слой настоящий, координаты точные, и прогонять такую страницу через модель — вносить ошибку туда, где её не было. Заодно отпадают словарь, расстояние Левенштейна и добор потерянных боксов — исправлять нечего.

```
PDF
  → mupdf: строки текста с координатами + отрисовка страниц в PNG
  → колонки берутся из строки заголовка таблицы, не из зашитых чисел
  → строки дней: одна на дату, пустая = «смены нет»
  → отсечка дней за датой Julkaistu — их пустоте верить нельзя
  → шлюз: смена против своих активностей; отпуск и метки — не смена
  → не прошедшее шлюз → в ревью как «требует внимания»
```

**Единица разбора — документ, а не страница.** Граница публикации написана в шапке первой страницы, а строки дней продолжаются на следующих, где шапки таблицы уже нет.

**Страницы хранятся как обычные кадры** (D-030). Каждая отрисовывается в PNG и попадает в ту же таблицу `screenshots`, что и снимки экрана: экран проверки показывает их одинаково и не знает, чем загрузили. Оригинал PDF хранится рядом — разбор идёт по тексту, а текста в картинке нет.

**Одна зависимость на обе задачи** (D-029). `mupdf` (WebAssembly, 14 МБ) и достаёт текст с координатами, и рисует страницы. Альтернатива — `pdfjs-dist` плюс `@napi-rs/canvas`: две зависимости, 68 МБ и нативный бинарник в образе.

**Что проверяет шлюз.** Дня недели в выгрузке нет, сверять дату не с чем и незачем — она написана целиком, вместе с годом. Зато у смены есть независимая расшифровка: строки активностей, из которых она состоит. Их края обязаны сойтись с краями смены. Код смены в проверке не участвует (3.6); из него время берётся только тогда, когда колонка со временем пуста, и это подписано в ревью.

**Что не идёт в календарь.** Отпуск и служебные метки опознаются по названию активности и помечаются `non_work_marker` с пройденным шлюзом: строка прочитана верно, это не сбой разбора, поэтому «требует внимания» на ней не загорается. День с отпуском при этом утверждает про дату то же, что фраза «смены нет»: если событие на эту дату уже стоит, оно удаляется.

**Скорость.** Двухстраничный отчёт за месяц — 53 мс на чтение и разбор, отрисовка страницы A4 в двойном масштабе — 65 мс. Сети не требуется вовсе: ни весов, ни внешних запросов.

## 7. Диффинг и правила применения

### 7.1. Область действия

**Импорт трогает только те даты, которые явно присутствуют в загруженных скриншотах.** Даты, которых в пачке нет, не изменяются никогда. Без этого правила загрузка одного скрина снесла бы весь остальной месяц.

### 7.2. Алгоритм

Для каждой даты `D`, встреченной в батче:

```
desired = смены, распознанные для D          (может быть пусто → «нет смены»)
current = смены в БД для D
сопоставление по паре (starts_at, ends_at):

  есть в обоих        → skip_identical   ничего не делаем
  только в desired    → create           создать событие
  только в current    → delete           удалить событие
```

Правила из постановки получаются из этого автоматически:

| Ситуация | Результат |
|---|---|
| Графика на дату нет | `create` |
| График есть, время совпадает | `skip_identical` |
| График есть, время не совпадает | `delete` + `create` |
| `Sinulla ei ole työvuoroa` | `delete` (если было что удалять) |

### 7.3. Одно отступление от буквы постановки

Когда на дате ровно одна смена и до, и после, вместо `delete` + `insert` предлагается **`events.update`** — тот же результат в календаре, но:

- сохраняется `google_event_id`, а с ним персональные напоминания, которые владелец календаря мог поставить на событие;
- подписчики календаря не видят «событие исчезло / событие появилось».

Управляется флагом:

```
GCAL_UPDATE_STRATEGY=update    # update (по умолчанию) | recreate
```

`recreate` даёт буквальное поведение из постановки. Переключается одной переменной, если предпочтение иное.

### 7.4. Конфликты между скриншотами

Если две даты из разных скринов противоречат друг другу (в одном смена 8–14, в другом 9–15 на ту же дату), запись **не применяется автоматически** — она попадает в ревью помеченной как конфликт, с указанием обоих источников. Молчаливое «побеждает последний» здесь недопустимо: порядок скринов задаёт пользователь, и он произволен.

## 8. Интеграция с Google Календарём

### 8.1. Аутентификация — сервисный аккаунт

Никакого OAuth. Порядок:

1. В Google Cloud Console создать проект → включить **Google Calendar API**.
2. Создать **Service Account**, скачать JSON-ключ.
3. Скопировать адрес сервисного аккаунта — вида `shift-sync@<проект>.iam.gserviceaccount.com`.
4. В Google Календаре открыть календарь **«Смены»** → **⋮** → *Настройки и общий доступ* → **Открыть доступ определённым пользователям** → добавить этот адрес с правом **«Внесение изменений в мероприятия»**.
5. Там же скопировать **ID календаря** и положить в `GCAL_CALENDAR_ID`.

Токен сервисный аккаунт выписывает себе сам, срок жизни бесконечный, экран согласия не нужен.

> Почему не обычный OAuth: у приложения в статусе *Testing* Google отзывает refresh-токен **каждые 7 дней**. Чтобы этого избежать, приложение нужно переводить в *Production* и проходить верификацию. Для домашнего сервиса это несоразмерно.

### 8.2. Как сервис отличает свои события от чужих

Каждое созданное событие помечается приватным свойством:

```ts
extendedProperties: {
  private: {
    app:         'fc-shift-sync',
    shiftId:     '<uuid>',
    workDate:    '2027-03-15',
    fingerprint: '2027-03-15T07:00/14:00',
  },
}
```

Выборка — только по своей метке:

```ts
calendar.events.list({
  calendarId,
  privateExtendedProperty: ['app=fc-shift-sync'],
  timeMin, timeMax,
});
```

**Это жёсткая гарантия: личные события владельца календаря сервис не видит и тронуть не может.** Обязательное условие записи в общий календарь, а не в отдельный.

### 8.3. Форма события

```ts
{
  summary: 'Работа 07:00–14:00',
  description: 'Demo Market\n410 7-14\nVuoroaika: 7 h\n\nИмпорт от 05.03.2027',
  start: { dateTime: '2027-03-15T07:00:00', timeZone: 'Europe/Helsinki' },
  end:   { dateTime: '2027-03-15T14:00:00', timeZone: 'Europe/Helsinki' },
  colorId: '11',
  extendedProperties: { private: { /* см. выше */ } },
}
```

Время передаётся **локальное + `timeZone`**, а не UTC — тогда переход на зимнее время в конце октября Google обрабатывает сам. Если бы мы слали UTC, смены после смены времени поехали бы на час.

### 8.4. Сверка (reconcile)

Отдельная операция, вручную с экрана истории или по расписанию: выбрать свои события за окно ±60 дней, сравнить с `shifts`, показать расхождения (событие удалили руками в Google, отредактировали время, осталось «осиротевшее» событие без записи в БД). Лечит дрейф между БД и календарём.

### 8.5. Стоимость

Google Calendar API — 1 000 000 запросов в сутки бесплатно. Нам нужно порядка 30 в месяц.

## 9. Аутентификация в сервисе

```
POST /api/auth/login  { password }
  → сравнение с APP_PASSWORD через timingSafeEqual
  → JWT в HttpOnly + Secure + SameSite=Lax cookie, срок 30 дней
  → подпись SESSION_SECRET

Глобальный AuthGuard, декоратор @Public() только на /auth/login и /health
@nestjs/throttler на логине: 5 попыток / 15 минут / IP
```

Пароль не хранится в БД и не логируется. **Если сервис выставляется в интернет — только по HTTPS**, иначе пароль уходит открытым текстом. Для домашнего сценария достаточно локальной сети или Tailscale.

## 10. API

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/api/auth/login` | вход по паролю |
| `POST` | `/api/auth/logout` | выход |

## 11. Фронтенд

Nuxt 4 + Nuxt UI v4, DDD по доменам как в DC. Рендеринг — SPA (`ssr: false`), сборка в статику, раздаётся самим NestJS через `ServeStaticModule`. Один процесс, один порт, нет CORS.

**Проектировать под телефон в первую очередь** — скриншоты делаются на телефоне, и загружать их будут оттуда же.

| Экран | Содержание |
|---|---|
| `/login` | одно поле пароля |
| `/` | загрузка: drag&drop на десктопе, «выбрать из галереи» на телефоне, превью, прогресс распознавания |
| `/imports/:id` | **ревью** — главный экран, ниже |
| `/history` | список импортов, журнал `sync_log`, кнопка сверки |

### Экран ревью

Таблица по датам, отсортированная по возрастанию:

```
 ☑  дата           было           станет          действие
────────────────────────────────────────────────────────────────
 ☑  вс 07.03       —              07:00–14:00     создать
 ☑  пн 08.03       10:00–16:00    10:00–16:30     обновить
 ☑  вт 09.03       09:00–17:00    09:00–17:00     без изменений
 ☑  ср 10.03       08:00–14:00    —               удалить  ← «нет смены»
 ⚠  чт 11.03       —              01:00–01:01     отброшено: TES V, 1 мин
 ☑  пт 12.03       —              08:30–15:00     создать
```

- время редактируется прямо в строке;
- строки «требует внимания» подсвечены и по умолчанию **не отмечены** — их нужно осознанно включить;
- рядом со строкой — кроп исходного скриншота, чтобы сверить глазами не открывая галерею;
- внизу сводка: «создать 3 · обновить 1 · удалить 1 · без изменений 1 · отброшено 1» и кнопка **«Применить»**.

## 13. Инфраструктура и запуск

```yaml
# infrastructure/postgresql/docker-compose.yml
name: fc-postgresql
services:
  postgresql:
    image: postgres:17
    container_name: fc-postgresql
    restart: unless-stopped
    ports: ["5481:5432"]                # не 5432: не мешать локальному PostgreSQL
    environment:
      POSTGRES_USER: fc_admin
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: fc_shift_sync
      TZ: UTC
    volumes: ["fc-postgresql-data:/var/lib/postgresql/data"]
```

Больше ничего поднимать не нужно: распознавание живёт внутри процесса `api`, отдельного демона у него нет.

**Где крутить:** дома, на обычном ПК. Памяти и потоков домашней машины хватает с запасом, данные никуда не уезжают, стоимость нулевая. Доступ с телефона — по локальной сети или через Tailscale. Бесплатные облачные варианты (Cloud Run + Neon) возможны, но там придётся отказаться от локальных моделей — а это прямо противоречит приоритету.

## 16. Риски

| Риск | Вероятность | Что делаем |
|---|---|---|
| ORTEC поменяет вёрстку приложения | **низкая, специально не готовимся** | Приложение стабильно, изменений в обозримом будущем не ожидается. Если случится — `ocr-bench` покажет первым же прогоном, парсер вынесен в отдельный модуль и переписывается за вечер |
| Локальная модель хуже облачной по качеству | **снят** | Проверено: 9/9 на реальных кадрах и на синтетике, воспроизведено в контейнере. Шлюз не пропустит брак дальше — в худшем случае вырастет доля строк «требует внимания» |
| Список пересекает границу месяца | средняя | Месяц берётся не из шапки, а из каждой строки (`syyskuuta` есть в каждой). Год — из шапки, при переходе через декабрь корректируется |
| Скриншоты содержат персональные данные | **низкая** | Обрабатываются и хранятся только локально, `SCREENSHOT_RETENTION_DAYS` чистит по расписанию. Наружу они не уходят вообще: облачных провайдеров в коде нет |
| Пароль в ENV утечёт | низкая | Не логируется, `.env` в `.gitignore`, сервис не выставляется в интернет без HTTPS |
| Сервис удалит чужое событие | **исключено** | Выборка строго по `privateExtendedProperty=app=fc-shift-sync`. События без этой метки невидимы для сервиса |

## 17. Открытые вопросы

1. **Формулировка заголовка события** — `Работа 08:00–14:00`, или код смены `410 7-14`, или просто `Работа`? Влияет на то, как это читается в общей сетке семьи.
2. **Горизонт импорта** — принимать ли скриншоты за прошедшие даты, или отбрасывать всё раньше сегодняшнего дня?
3. **Отдельный календарь вместо общего личного** — если завести календарь `Работа`, смены можно будет отключать одной галочкой, не трогая личные события. Технически с метками безопасно и так; вопрос удобства.
4. **Уведомления** — ставить ли напоминание за N минут до смены при создании события, или оставить настройку календаря по умолчанию.
